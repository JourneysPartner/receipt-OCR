## A. 直す ── 高（2 件）

### A-1【高】読み戻しが実機では必ず不一致になり、保存した形式が即座に無効になる

**場所**：`src/19_FormatRegistration.gs` の `formatDerivedSpec_`（`lookbackMonths: base ? base.lookbackMonths : undefined` の 2 行、449〜450 行付近）と `formatReadbackCellsEqual_`（679〜694 行付近）。

**何が起きるか**：既存の形式の `lookbackMonths`・`forwardMonths` は空だと `null` です（`formatRowFromValues_` の `detectorOptionalCount_`）。それを `spec` に `null` のまま入れるので、`cardFormatRowValues_` の Y・Z（添字 24・25）が `null` になり、`null` のままシートへ書かれます。**実機のシートは `null` を持てず空セルになり、`readRowByNumber_`（Sheets API・`UNFORMATTED_VALUE`）は空セルを返さないので `padRowValues_` が `''` で埋めます。**比較は `String(null)` と `String('')` で必ず不一致になり、**土台のある登録（ほぼすべての登録）が保存した直後に `READBACK_MISMATCH` で無効になります。**スタブは書いた `null` をそのまま返すので、1163 本は緑のままでした（監査で `installCardFormat` → `readRowByNumber_` を実行して確認）。

**直し方**：仕様書 §5.5 の Y・Z の行と §5.7 手順 7(a)。(1) 導出で `null` を作らない（`null` は `undefined` にする。`cardFormatRowValues_` が `''` にする）。(2) 比較で `null`・`undefined`・`''` を同じとみなす。**両方やること**（1 つ目だけだと、将来ほかの列で同じことが起きる。2 つ目だけだと、シートに `null` を書く経路が残る）。

**テスト**：fmt 30b。**「読み戻しの読取を、実機と同じく `null` を `''` にして返すものに差し替えても `readback: 'OK'`」を必ず入れること**（そうしないとこの欠陥はまたスタブの上で見えなくなる）。変異 M20・M21 がそれぞれ赤になること。

### A-2【高】保存が `ok: false` を返すと画面全体が固まる

**場所**：`src/81_WebAppUi.html` の `saveFormat`（1940〜1946 行付近）と `renderFormatSaved`（1776〜1780 行付近）。

**何が起きるか**：試し読みから保存までの間に、その要確認がメニューや別のタブで扱われると、`webAppSaveFormat` は `{ok: false, code: 'NOT_FORMAT_UNKNOWN'}` を返します。`result.saved === false` ではないので成功として `state.formatSaved` に入り、`renderFormatSaved` が `saved.after.count` で例外を投げます。それが `finally` の `formatSetBusy(false)` → 再描画の途中で起きるので、ファイル一覧・フォルダ・記帳のボタンが無効のまま残り、再読込するまで戻りません。

**直し方**：仕様書 §7.11 U1。試し読み・要修正へ・診断・取込待ちへ戻すでも同じ形を点検すること。

**テスト**：fmt 74。変異 M24 が赤になること。
