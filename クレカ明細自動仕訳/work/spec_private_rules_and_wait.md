## 5. D：優先の言葉で科目が決まる行は取引先を立てない

### 5.0 金券系の言葉は、仕入れの言葉と一緒なら仕入れに譲る（`38` の `resolveAccountCode_`）

優先の絞り込み（`preferred` を作った直後、`if (preferred.length) hits = preferred;` の所）を次のようにする。

1. `yieldKeys` ＝ `ACCOUNT_YIELD_TO_PURCHASE_WORDS_` の各語の `usageWordKey_`。
2. `purchaseHits` ＝ 当たり（`hits`）のうち、優先でなく（`row.priority !== true`）、`row.code === ACCOUNT_PURCHASE_CODE_` の行。
3. **`preferred` が 1 つ以上あり、その全部の `row.key` が `yieldKeys` に入っていて、`purchaseHits` が 1 つ以上ある**とき：`hits = purchaseHits`（優先の言葉は全部捨てる）。この道で決まった結果には `priority` を付けない（§5.1）＝取引先は今どおり照合する。
4. それ以外は今と同じ（`preferred` があれば `hits = preferred`）。

- 例：`金券ショップで仕入`・`商品券 仕入代`・`クオカード 商品代` → 712。`金券`・`金券 送料`・`金券 消耗品` → 294（譲るのは仕入高の言葉だけ）。`私用 金券 仕入`・`私用 仕入` → 294（金券系でない優先の言葉が 1 つでもあれば今と同じ）。
- 「誤りの行が当たりに 1 つでもあれば決めない」は、この絞り込みより前にあるので今のまま。
- 後ろの手順（先頭・最長・コードが 1 つ・一覧の確かめ）は `purchaseHits` に対して今のまま進む。

### 5.1 `resolveAccountCode_`（`38`）の戻り値に `priority` を足す

- 優先の絞り込みで `hits = preferred` になり（§5.0 の 4。仕入れに譲った §5.0 の 3 は含めない）、その言葉から**コードが 1 つに決まった**とき（＝`AMBIGUOUS` を返さなかったとき）、その後に返す値（`MATCHED`・`NEEDS_LIST_ENTRY`・`NOT_IN_SHEET_LIST`・勘定科目一覧の都合の `INVALID_ENTRY`）に `priority: true` を付ける。
- それ以外の戻り値（`NO_MATCH`・`AMBIGUOUS`・当たりに誤りの行があるときの `INVALID_ENTRY`・優先でない言葉で決まったとき）には `priority` を付けない（`undefined`）。
- 今ある欄（`status`・`code`・`word`・`name`）の値は 1 つも変えない。

### 5.2 取込の 8-10（`71`）

`transactions.map` の中で、**`accountMasters` があるときだけ**、用途の当たりを取引先の判定より前に求める。

```
var merchantRule = accountMasters ? merchantAccountRule_(tx.merchantOriginal) : null;
var purposeResolution = accountMasters && !merchantRule ?
  resolveAccountCode_(tx.purpose, customer, accountMasters, accountSheetList) : null;
var cashback = isCashbackMerchant(customer, tx.merchantOriginal);
var exempt = cashback || isPartnerExemptPurpose(customer, tx.purpose) ||
  Boolean(merchantRule && merchantRule.withoutPartner === true) ||
  Boolean(purposeResolution && purposeResolution.priority === true);
```

- 後ろの `accountResolution` は、店名の規則に当たれば今どおり `resolveMerchantAccountCode_`、そうでなければ **上で求めた `purposeResolution` をそのまま使う**（`resolveAccountCode_` を 2 回呼ばない）。
- `exempt` の後の道は今のまま（照合しない・`planned.f = ''`・`RESOLVED_WITHOUT_PARTNER`・取引先の要確認を作らない）。
- **取引先を立てないのは、優先の言葉でコードが 1 つに決まったことだけで決まる**（C が一覧の都合で書けなくても立てない。店名の規則と同じ考え方）。
- 優先の言葉が当たっても決まらなかった行（`AMBIGUOUS`・誤りの行）は、今どおり取引先を照合する（安全側）。
- 新しい読取・書込は無い。

## 6. E：取込の待ち（最後に更新したのが自分ならかけない）

### 6.1 考え方

10 分の待ちは「顧客がまだ編集しているファイルを取り込まない」ための守りである。システムは画面を押した人（今はオーナー）として動き、名前の頭を変えるとその人が「最後に更新した人」になる。Drive の `lastModifyingUser.me`（この呼出しをしている本人が最後に更新したか）が `true` のときだけ、待ちをかけない。

**守り（変えない）：**`lastModifyingUser` が無い・`me` が `true` でない・読めないときは、今と同じく待つ。

### 6.2 走査（`10_DriveScanner.gs`）

- `Drive.Files.list` の `fields` の `files(...)` に `lastModifyingUser(me)` を足す。`driveShortcutTargetMetadata_` の `fields` にも `lastModifyingUser(me)` を足す。**呼出しの数は増やさない。**
- 純粋な関数を 1 つ足す：

```
/** 最後に更新したのが、この呼出しをしている本人か。分からなければ false。 */
function driveModifiedByMe_(file) {
  return Boolean(file && file.lastModifyingUser && file.lastModifyingUser.me === true);
}
```

- `scanUnprocessedFiles` の判定：`modified <= stableBefore` に加えて、`driveModifiedByMe_(見る相手)` が `true` なら候補にする（待ちの材料 `waiting` にも入れない）。
  - 見る相手：ショートカットは**指す先**（今 `modifiedTime` を指す先で置き換えているのと同じ場所で、`file.lastModifyingUser = target.lastModifyingUser || null` も置き換える）。指す先が読めなかったときは今と同じ道（自身の値のまま）で、そのときは**待ちを外さない**（`lastModifyingUser` を `null` にする）。
  - 未登録のファイルにも同じに効かせる（オーナー自身が置いたファイルは待たない）。
- `getFileMetadataBatch`（再走査）は変えない。

### 6.3 画面の一覧と案内（`80_WebApp.gs`）

走査と画面の表示がずれないようにする（`webAppStableWaitMinutes_` の注釈のとおり）。

- `webAppFolderFile_`：`minutes > 0` のファイルだけ、`Drive.Files.get(見る相手の ID, {fields: 'lastModifyingUser(me)', supportsAllDrives: true})` を 1 回呼び、`driveModifiedByMe_` が `true` なら `minutes = 0` にする。見る相手はショートカットなら指す先（指す先の日時が読めず自身の日時で待つ道では、呼ばずに今のまま）。呼出しが失敗したら今のまま待つ（例外を外へ出さない）。`minutes === 0` のファイルでは呼ばない。
- `webAppRecheckCustomerFixFile`・`webAppRecoverStuckFile` の `waitMinutes`：同じ決め方にする（小さな関数にまとめて 3 か所から使う。名前は実装者が決めて報告）。
- `webAppStableWaitMinutes_` そのものは変えない。

### 6.4 知っていて受け入れること（§13 にも書く）

- 顧客が直した直後に、オーナーが画面で「取込待ちに戻す」を押すと、名前の変更でオーナーが最後に更新した人になり、待ちなしで取り込める。押した人が「直し終わった」と確かめた、とみなす。
- オーナー自身が明細を編集して 10 分以内に記帳すると待たない。
- スタッフが画面を使うようになったら（K-W1）、`me` は「画面を押した人」になる。そのとき見直す。

## 9. 安全の条件（テストで確かめる）

1. C の列を設定していない顧客は、A〜D に当たる用途・店名でも、C・F・G・取引先の状態・要確認・読取と書込の回数が今と同じ。
2. 優先の言葉でコードが 1 つに決まった行だけ、取引先を立てない。優先でない言葉（`梱包`・`仕入` など）で決まった行・決まらなかった行（`AMBIGUOUS`・誤りの行・`NO_MATCH`）は、今どおり照合する。
3. 個人には 294 だけ、法人には 362 だけ。逆は書かない。
4. 店名の規則は店名の全体が同じときだけ当たる。
5. 「サプリ」は用途にあるときだけ効く。店名にあっても効かない。課対仕入でない科目（事業主貸 など）の行には効かない。
6. 待ちを外すのは `lastModifyingUser.me === true` のときだけ。`false`・欄が無い・`lastModifyingUser` が無い・`null`・指す先が読めないときは、今と同じく待ち、`waiting` にも今と同じく入る。
7. Sheets の `batchGet`・`batchUpdate` の数は、取込・一覧・要確認の一覧のどれも今と同じ。Drive の呼出しは、走査では増えない。画面の一覧では「10 分以内のファイルの数」だけ増える。
8. freee の止めの理由の文字と使用用途の値は、HTML として解釈されない。
9. 既存のテストは直さない（種の行数・列の数を数えているテストだけ、数を合わせてよい。直した所は全部報告する）。落ちたら止めて報告する。
