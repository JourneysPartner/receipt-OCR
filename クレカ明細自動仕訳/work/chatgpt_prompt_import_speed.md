# ChatGPT へ貼る文章（取込の高速化）

---

Google Apps Script（コンテナバインド）で動いている、クレジットカード明細の自動記帳システムの**性能設計**について相談します。コードは見せられないので、**実測値と制約**だけで考えてください。

## やっていること

1. Google Drive の顧客フォルダにカード明細ファイル（`.xlsx` が主、一部 `.csv`）が置かれる
2. GAS がそれを読み、カード会社ごとの形式を判定して取引行を抽出する
3. Google スプレッドシート（freee へ取り込むための出納帳。残高計算の数式が入っている）へ転記する
4. 書いた行を**読み返して値が一致することを確認**してから確定させる
5. 取引先が辞書で一意に決まらない行は「要確認」として人の判断待ちにする

会計処理なので、**二重転記・取りこぼし・黙った上書きは許容できません。**

## 目標

**1カード12ヶ月分（12ファイル）を数分で終わらせたい。**いまは1ファイル 40〜100秒かかり、12ファイルで15〜20分です。

## 動かせない制約

- **GAS の1実行は6分で強制終了**される（`finally` も走らない）
- Sheets API の読取は**60回/分/ユーザー**の割当。超えると数十秒待たされる
- 1回のサーバー往復（セル範囲の読み書き）が**実測1〜3秒**かかる
- 転記先のシートは**残高数式を持つ**ので、`SpreadsheetApp.flush()` は再計算を伴う
- ファイル単位の排他制御（リース）と、処理ログ・恒久インデックスによる状態機械がある
- 書いた行の**読み返し確認**は外せない（会計上の要件）
- 監査ログはハッシュ連鎖になっている

## すでに測って、直したこと

| 施策 | 効果 |
|---|---|
| 監査ログ連鎖の検証（直近500行の SHA-256）を1ファイルごと→1押下ごとに | −56秒／呼出し |
| 取込前の整合性チェックを「顧客の全47ファイル」→「今回触る範囲」に | −209秒／呼出し |
| マスターシート読取前の `flush()` を省略（往復を23%削減） | **壁時計は1秒も変わらなかった** |

最後の1行が重要です。**往復回数を23%減らしても速くならなかった。**

## いまの実測（段階ごとの所要時間）

**ファイルA（取引3件・転記3件）合計43.4秒**

```
pre:total        8.1秒  前検証（取引ログへ一括登録、取引先照合の準備）
finish           4.9秒  状態遷移・処理ログ更新
dictionary       3.7秒  取引先辞書（約4,000行）の読込と索引構築
write:reserve    3.7秒  転記先の空き行を探して予約
register         3.0秒  処理ログ・恒久インデックスへ登録
read             3.0秒  Drive からファイル読込（.xlsx は変換を含む）
write:guard      2.8秒  ファイル変更ガード（ファイルを再読込して再ハッシュ）
processFile      2.7秒
duplicate        2.7秒  内容ハッシュと既存ファイルの突き合わせ
write:settle     1.9秒  取引ログの確定
lease            1.7秒  排他ロックの取得
write:values     1.4秒  転記先への値書込
enrich           1.1秒  用途補完・年補完・件数照合
parse/detect/match/destinationIndex/verify  計1.6秒
```

**ファイルB（取引9件）合計101.8秒** ── 同じ構成で、転記と要確認登録の部分だけが62秒に膨らむ

つまり **「1ファイル ＝ 定数20〜25秒 ＋ 取引件数に比例する分」**。定数側は 2〜8秒の処理が15個並んだもので、**突出した1箇所がありません。**

## 私がすでに検討して、効果が小さいと分かったもの

- **1回の呼出しで複数ファイルを処理**（呼出しごとの固定費を按分）── 固定費はもう13秒しかないので、12ファイルで2分強の節約にとどまる
- **`.xlsx` を Drive の変換に頼らず自前で解析**（ZIP展開＋XML）── 変換込みの読込が実測3秒なので、ここは元々ボトルネックではなかった

## 聞きたいこと

**12ファイルを数分に収めるために、どういう手が考えられますか。**

- 「2〜8秒の処理が15個」という形そのものを崩す方法（設計の作り替えを含む）
- GAS の6分制限を回避・活用する方法（複数実行の並列化、継続トリガー、非同期化など）── **その場合に会計上の整合性をどう守るか**まで含めて
- 1往復1〜3秒という単価そのものを下げる方法
- そもそも「GAS で全部やる」以外の構成（役割分担の見直し）

**私の前提そのものを疑ってくれて構いません。**測り方が間違っている可能性、目標設定が間違っている可能性も含めて指摘してください。
