## 【高】終端の取引に書き戻して、帳簿にゴースト行が生まれる

### 何が起きるか

`日付不明,未登録店,10800,仕入れ` の1行が **`DATE` と `PARTNER` の2件**の要確認を立てます。担当者が `DATE` 側で「対象外にする」を押すと、転記行は空になり取引は `CANCELED`。

**残った `PARTNER` は一覧に普通の対象として残ります。**操作画面はこうなります：

```
 1) 既存の取引先名を採用する（未解決 1 件のうち 1 件。残りは次回）
 2) 取引先なしで確定する（未解決 1 件のうち 1 件。残りは次回）
 3) 1 件だけ選んで対象外にする（転記行を空にします）（取引の状態 CANCELED では不可。管理者へ）
```

**3) だけが止まり、1) は押せます。**押すと空行に書き戻ります：

```
EXCLUDE後: (行が空)
ADOPT後  : ["", "", "株式会社テスト", "", "", "", "TX_7ffe…"]
```

利用日も金額も摘要も無く、**取引先名と内部IDだけの行**が顧客の入力用シートに残ります。取引ログ上は `CANCELED` なので、どの帳簿とも対応しません。`FIX_DATE_AMOUNT` ならさらに利用日と金額まで書き戻します。

そのうえ：
- 画面は「確定した要確認: 1 件」「ファイルの完了 → 完了 (COMPLETED)」と**成功を報告**します
- ファイルが `COMPLETED` になるので**もう誰も見に来ません**
- `44_IntegrityChecker` は `COMMITTED` しか見ないので整合性報告にも載りません
- `ADOPT` は取引先名を**辞書に学習**するので、取り消した判断が恒久ルールになります
- グループ一括でも起きます。`resolveOptionsFor_` はグループ先頭の取引しか見ないので、終端の1件が**画面に一度も表示されないまま**書き戻されます

### 原因

`src/96_Menu.gs:642-643` の条件が `code === 'EXCLUDE' || code === 'EXCLUDE_PRIOR_YEAR'` に限定されています。§7.3 の無効化規則の表がそう書いているためで、**実装は仕様書どおりです。**

### 直し方

条件を**取引単位の全操作**へ広げてください：

```js
} else if (definition.unit !== 'FILE' && live && live.transactionStatus &&
    [TX_STATUS.REVIEW_REQUIRED, TX_STATUS.COMMITTED].indexOf(live.transactionStatus) < 0) {
  disabledReason = '（取引の状態 ' + live.transactionStatus + ' では不可。管理者へ）';
}
```

レビュアーがサンドボックスで検証済みです：3経路すべてで**書込0・転記先不変**になり、全操作に `（取引の状態 CANCELED では不可。管理者へ）` が付き、**948/948 が緑のまま**でした。これは §7.9 行5 が求める「画面は行5の状態を『不可』と表示して隠さず」そのものです。

### あわせて直すもの

1. **この変異を赤にするテストを1本**（現状は緑です）。`runImport` で `DATE`＋`PARTNER` の2件が立つ材料を作り、`EXCLUDE` の後に `ADOPT_EXISTING_PARTNER` が**無効表示になり書込0**であることを確かめてください。
2. **仕様書 §7.3 の無効化規則の表**：第3行の対象欄を「`EXCLUDE`・`EXCLUDE_PRIOR_YEAR`」から「**取引単位の全操作**」へ。理由（終端取引の空行に書き戻すとゴースト行が生まれ、ファイルが `COMPLETED` になって二度と見直されない）も書いてください。
