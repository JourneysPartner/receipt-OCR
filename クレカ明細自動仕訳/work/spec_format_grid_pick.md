# 見本の表の上で列と行を選ぶ 仕様書

版 1.1（2026-11-08。1.0 に監査の記録 §9 と、行の「—」で試し読みを消さない直しを足した）

前提：形式不明カードの画面登録（`work/spec_format_registration.md`。§7.3〜§7.5 の画面）。

## 1. 背景

形式不明のファイルを画面で登録するとき、今は「見本の表」（§7.4）は見るだけで、列の役割（利用日・店名・金額・使用用途・予備金額）と見出し行・明細の開始行は、表の下の「列と形式の指定」（§7.5）のプルダウンと数値欄で決める。利用者から「見本の表の上で直接選べるように」と頼まれた（2026-11-08。プルダウンは残し、どちらで選んでも同じになる形をユーザーが選んだ）。

## 2. 範囲

- 変えるのは `src/81_WebAppUi.html` の形式の確認パネル（`renderFormatGrid`・`renderFormatInputs`・`formatColumnChoice`・`formatRefreshVisuals` と、そこから呼ぶ小さな関数）と CSS だけ。
- **変えないもの：**サーバー（`19_FormatRegistration.gs`・`80_WebApp.gs` ほか `src/*.gs` 全部）、回答（`answers`）の形、試し読み・保存・`previewHash`、確認のチェック（`acknowledgements`）の条件、診断の結果の見せ方、`customerSide` で［別の形式として登録する…］を押す前は表を出さないこと。

## 3. 決めたこと

1. **列の役割の選択欄：**見本の表の列記号の見出し（`th`）に、その列の役割を選ぶ選択欄を置く。
   - 選択肢は順に「—」（値 `''`）・利用日（`date`）・店名（`merchant`）・金額（`amount`）・使用用途（`purpose`）・予備金額（`amountFallback`）。名前は今の `formatRoleName` と同じ。
   - `th` の文字は列記号だけにする（役割は選択欄に出るので、今の「`B 利用日`」の文字は出さない）。
   - 選択欄は `<label>` で囲まない。名前は `aria-label`「`<列記号> 列の役割`」で付ける（表の中の選択欄が、下の「列と形式の指定」のラベルと取り違えられないようにするため）。
   - 選択欄の値＝今の回答でその列に付いている役割。役割が 2 つ以上付いている（提案がそうなっていた）ときは、上の選択肢の順で最初のもの。無ければ「—」。
2. **行の役の選択欄：**見本の表の行番号のセル（先頭の `td`）に、行番号の文字と、その行の役を選ぶ選択欄を置く。
   - 選択肢は順に「—」（値 `''`）・見出し行（`header`）・明細の開始行（`start`）。
   - `aria-label` は「`<行番号> 行目の役`」。`<label>` で囲まない。
   - 選択欄の値＝その行が見出し行なら `header`、明細の開始行なら `start`、どちらでもなければ `''`。見出し行と明細の開始行が同じ行なら `header`。
3. **1 列に役割は 1 つ。**サーバーは同じ列に 2 つの役割を付けると止める（`COLUMN_ROLE_DUPLICATE`、§6.1）ので、画面でも重ならないようにする。
   - 列 X で役割 R を選ぶ：`answers.columns[R] = X`。ほかの役割で X を指していたものは `null` にする。
   - 列 X で「—」を選ぶ：X を指していた役割を全部 `null` にする。
   - **下のプルダウンで役割 R に列 X を選んだときも同じ規則**（ほかの役割で X を指していたものは `null`）。どちらで選んでも同じ答えになるようにするため。プルダウンで「なし」を選んだときは R だけ `null`（今と同じ）。
   - 値が変わった役割は全部「手で選択」の扱いにする（`state.formatManualColumns[role] = true`）。`null` にされた役割の出どころの表示は、予備金額なら「なし」、ほかは「手で選択」（今のプルダウンで「なし」を選んだときと同じ）。
4. **金額の候補が 2 列以上のとき**（今は金額をプルダウンでなく候補の一覧（ラジオ）で選ぶ）：表の「金額」は、候補の一覧に出ている列（`formatAmountChoices` が返す列。参照ファイルの列を含む）でだけ選べる。ほかの列の選択欄では「金額」の選択肢を `disabled` にする。候補が 1 列以下のときは、どの列でも選べる。
5. **行の役を選んだとき：**
   - 行 n で「見出し行」：`answers.headerRow = n`。明細の開始行が n 以下なら `answers.dataStartRow = n + 1` にする（サーバーの提案と同じ寄せ方。`19` の `formatProposal_` の「開始行が見出し行以下なら見出し行の次」）。表に n + 1 行目が無くても答えは n + 1。
   - 行 n で「明細の開始行」：`answers.dataStartRow = n`。見出し行は動かさない（n が見出し行以下なら、今と同じく試し読みで止まる）。
   - 「—」を選んだ：答えは変えない。選択欄は今の値（見出し行・開始行・`''`）に戻す。見出し行と開始行は必ずどこかの行にあるので、外すことはできない。
6. **変更の通り道：**表の選択欄の変更は、今のプルダウン・数値欄と同じ `formatUpdateAnswer` を通す。だから、取込などの最中（`isMutationBusy()`）や保存した後（`state.formatSaved`）は答えが変わらず、試し読みの結果は古いものとして消え（`previewHash` を捨て、保存を押せなくする）、確認のチェックは今と同じ条件で出し直される（使用用途の列を変えたら、見出しが「使用用途」でない列への警告とチェック）。
7. **両方をそろえる（`formatRefreshVisuals`）：**どちらで変えても、変えた後の答えに次をそろえる。**パネルや表を作り直さない**（入力中の要素とスクロールの位置を保つ。fmt 82・fmt 103 と同じ考え）。
   - 表：列の選択欄の値（決定 1）と、「金額」の選択肢の `disabled`（決定 4）。行の選択欄の値（決定 2）。行の強調（`format-header`・`format-start`、今と同じ）。**`th` の `textContent` を書き換えて選択欄を消さない。**
   - 下：見出し行・明細の開始行の数値欄は、**欄の値を数にしたものが答えと違うときだけ**書き換える（数値欄に打っている途中の空欄に 0 を書き込まない）。列のプルダウンの値と、ラベルの出どころの表示。金額の候補の一覧の `checked`。プルダウンの選択肢の文字（列記号・見出し・先頭の値）は今と同じく見出し行・開始行に合わせて書き換える。
8. **使えないとき：**表の選択欄は、下のプルダウンと同じ条件（`isMutationBusy() || Boolean(state.formatSaved)`）で `disabled` にする。
9. **見た目：**表の中の選択欄は小さく（文字は 12px 程度、余白は小さく）、列の幅を広げすぎない。見出し行・開始行の強調の色は今のまま。
10. **安全：**選択欄の選択肢の文字は決まった語だけ。セルの値・見出しの文字は今と同じく `textContent` で出す（HTML として書き込まない）。

## 4. 変更の中身（`src/81_WebAppUi.html` だけ）

- `renderFormatGrid`：決定 1・2・8・9。表の選択欄は `state.formatGridColumnSelects`（列記号の順）・`state.formatGridRowSelects`（行番号の順）に持つ。**今の `state.formatColumnSelects` には入れない**（下のプルダウンだけを持つ配列のまま）。
- 共通の割当て関数（名前は任せる。例 `formatAssignColumn(role, letter)`・`formatClearColumn(letter)`）：決定 3。表と下のプルダウンの両方から使う。
- `formatColumnChoice`：プルダウンの変更を共通の割当て関数に通す（決定 3）。プルダウンがどの役割のものかを後で引けるようにする（`state.formatColumnSelects` と同じ順の配列や `dataset.role` など）。
- `renderFormatInputs`：数値欄と金額の候補のラジオを後でそろえられるように持つ。
- `formatRefreshVisuals`：決定 7。
- CSS：決定 9。

## 5. テスト（`test/phase9-format-registration.test.js` に足す。grid 1〜10）

見本の表は `mountedFormatWorld()` の診断（列 A〜E・行 1〜3、提案は A 利用日・B 店名・C 金額・D 使用用途・予備金額なし、金額の候補 C・E、見出し行 1・開始行 2）を使う。表の選択欄は `aria-label` で探す。

1. **grid 1：**表の 5 列の選択欄の値が `date`・`merchant`・`amount`・`purpose`・`''`、行の選択欄が `header`・`start`・`''`。`aria-label` が決定 1・2 のとおり。`th` の文字（選択欄を除く）は列記号だけ。表の選択欄はどれも `<label>` の中に無く、`state.formatColumnSelects` は 4 個のまま。
2. **grid 2：**表で E 列を「利用日」にする → `answers.columns.date === 'E'`、下の「利用日」のプルダウンの値が `E`、ラベルが「利用日（手で選択）」、A 列の表の選択欄が `''`、試し読みの結果と `formatHash` が消えて保存が押せない。表（`table`）・下のプルダウン・表の選択欄は同じ要素のまま（作り直さない）。
3. **grid 3（1 列 1 役・表から）：**表で A 列を「店名」にする → `merchant === 'A'`、`date === null`、B 列の表の選択欄が `''`、下の「利用日」のプルダウンが `''`。続けて A 列で「—」→ `merchant === null`。
4. **grid 4（1 列 1 役・プルダウンから）：**下の「利用日」で `B` を選ぶ → `date === 'B'`、`merchant === null`、B 列の表の選択欄が `date`、A 列が `''`、下の「店名」が `''`。プルダウンで「なし」を選ぶと、その役割だけ `null`（ほかは変わらない）。
5. **grid 5（行）：**3 行目で「見出し行」→ `headerRow === 3`・`dataStartRow === 4`、数値欄が `3`・`4`、3 行目に `format-header`、1 行目の強調が消える、下のプルダウンの選択肢の文字が 3 行目の見出しに変わる。続けて 1 行目で「明細の開始行」→ `dataStartRow === 1`・`headerRow === 3`（見出し行は動かない）。開始行が見出し行より下にあるとき（見出し 1・開始 3 にしてから 2 行目を「見出し行」）は開始行を動かさない。
6. **grid 6（「—」）：**見出し行の行で「—」を選ぶ → 答えは変わらず、選択欄は `header` に戻る。何も役の無い行で「—」を選んでも答えは変わらない。
7. **grid 7（金額の候補）：**候補が 2 列（C・E）のとき、表の A・B・D 列の「金額」の選択肢が `disabled`、C・E 列は選べる。E 列で「金額」→ `amount === 'E'`、ラジオの E が `checked`・C が外れる、C 列の表の選択欄が `''`。候補を 1 列にした診断では、どの列でも「金額」が選べ、選ぶと下の「金額」のプルダウンの値が変わる。参照ファイルの金額の列（候補に無い列）も選べる。
8. **grid 8（確認のチェック）：**表で E 列（見出し「予備」）を「使用用途」にする → 今のプルダウンで選んだときと同じ、見出しが「使用用途」でない列の警告と「入力ミスを様式として登録することを理解した」のチェックが出る。
9. **grid 9（使えないとき）：**取込の最中（`state.importBusy = true` で描き直す）と保存した後（`state.formatSaved` を置いて描き直す）は、表の選択欄が全部 `disabled`。`disabled` を外して変更を起こしても答えが変わらない。
10. **grid 10（数値欄）：**見出し行の数値欄を空にして変更を起こす（打っている途中）→ 欄の値は空のまま（`0` を書き込まない）。数値欄で `2` を入れたら、表の 2 行目の選択欄が `header` になる。

**直してよい既存のテスト（これだけ）：**
- fmt 94：`format-body` の最初の `select` を下の「利用日」のプルダウンだと仮定している。表に選択欄が増えるので、下のプルダウンを名前で取る形に直す（確かめる中身は変えない）。
- fmt 103：「`E 利用日`」の見出しの文字の確かめを、E 列の表の選択欄の値が `date` であることの確かめに置き換える（決定 1 で見出しの文字は列記号だけになるため）。
