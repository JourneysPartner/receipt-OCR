# 形式の確認パネルの下の入力欄をなくす 仕様書

版 1.0（2026-11-08）

前提：`work/spec_format_grid_pick.md`（gas-push-136。見本の表の上で列の役割と見出し行・開始行を選べる）。

## 1. 背景

gas-push-136 で見本の表の上で列と行を選べるようにした。利用者から「下の『列と形式の指定』の部分はいらない。上の『いちばん近い形式』の選択欄のあたりに、形式 ID・形式名を書ける箇所を作って」と頼まれた（2026-11-08）。

## 2. 範囲

- 変えるのは `src/81_WebAppUi.html` の形式の確認パネルだけ。**サーバー（`src/*.gs`）は変えない。**回答（`answers`）の形・試し読み・保存・`previewHash`・確認のチェックの条件・1 列 1 役の規則（`formatAssignColumn`・`formatClearColumn`）・見本の表の選択欄の動きは変えない。

## 3. 決めたこと

1. **なくすもの（`renderFormatInputs`）：**見出し「列と形式の指定」、見出し行・明細の開始行の数値欄、利用日・店名・使用用途・予備金額のプルダウン、見出し「金額の列」とその下（金額のプルダウン、または候補が 2 列以上のときの候補のラジオの一覧）。列と行は見本の表の選択欄だけで選ぶ。
2. **残すもの：**確認のチェックの置き場（`state.formatAcknowledgementHost`。「入力ミスを様式として登録することを理解した」「金額の列を確認した」と警告の文）、［試し読み］・［保存して有効にする］。置く場所は今と同じく見本の表の下。
3. **形式 ID・形式名の欄は上へ：**見本の表の見出し「見本の表」の**直前**に、1 行（`action-row`）で「形式 ID」「形式名」の文字の欄を置く。`NEAR` のときは「いちばん近い形式」の選択欄のすぐ下、新しい形式（近い形式なし）のときは「近い形式がありません…」の文の下に来る。
   - 欄の作りと動きは今の `formatField` のまま（ラベルの文字は「形式 ID」「形式名」、変更は `formatUpdateAnswer` を通す、`disabled` の条件は `isMutationBusy() || Boolean(state.formatSaved)`）。
   - 出す条件は見本の表と同じ（`customerSide` で［別の形式として登録する…］を押す前は出さない。`MATCHES_ACTIVE`・`AMBIGUOUS` では出さない）。
   - 打っている途中の欄を書き換えない（今と同じく、変更のたびにパネルを作り直さない）。
4. **金額の候補の比べは試し読みの結果へ：**今は候補が 2 列以上のとき、下のラジオの一覧に候補ごとの「列記号「見出し」 先頭の値 合計 ¥… 相違 n 行」が出ている（試し読みの後）。金額の列の選び間違い（手数料の列など）に気づくための情報なので、なくさずに「試し読みの結果」（`renderFormatPreview`）の件数・合計の行の下へ移す。
   - 出すのは候補が 2 列以上で、試し読みの結果に `extraction` があるときだけ。小見出し「金額の候補」の下に、`formatAmountChoices(proposal, answers, grid)` の順で 1 候補 1 行：`<列記号>「<見出し>」 <先頭の値> 合計 <金額> 相違 <n> 行`。数は今のラジオの一覧と同じ求め方（`amountComparison` の同じ列のもの。無くて選んだ列なら `extraction.total` と相違 0）。比べが無い候補は合計・相違を出さない。
   - 今選んでいる列の行の末尾に「（選択中）」。
   - 文字は `textContent` で出す。
5. **出どころの表示（「見出し」「参照ファイル」「手で選択」「要選択」）はなくなる。**プルダウンのラベルにだけ出ていたため。`state.formatManualColumns` は回答の記録として今のまま更新してよい（使われなくなるなら消してもよいが、どちらにしたか報告）。
6. **`formatRefreshVisuals`：**見本の表の選択欄・行の強調をそろえることだけ残す。なくした欄（`state.formatColumnSelects`・`state.formatRowInputs`・`state.formatAmountLabels`）をそろえる処理は消す。使われなくなった関数・状態は消す（`formatColumnChoice`・`formatColumnProvenance` など。ほかから呼ばれていないことを確かめてから）。
7. **試し読みの前の確かめ（`formatRequiredColumnMessage`）は今のまま**（「利用日の列を選んでください」など）。表で選んでいない役割があれば、今と同じくサーバーを呼ばずに知らせる。
8. **限られること（受け入れる）：**見出し行・開始行は見本の表に出ている行（サーバーの `formatGrid_`：1 行目から提案の開始行＋29 行目まで）からしか選べない。

## 4. テスト（`test/phase9-format-registration.test.js`）

新しいテスト compact 1〜6 を足す：

1. **compact 1：**パネルに「列と形式の指定」「金額の列」の文字が無く、`format-body` の中の `select` は見本の表の選択欄だけ（`NEAR` の近い形式の選択欄を除く）、`type="number"` の欄が無い、ラジオが無い。確認のチェックと［試し読み］［保存して有効にする］はある。
2. **compact 2：**「形式 ID」「形式名」の欄が見本の表より前にある（`format-body` の文字の並びで「形式 ID」が「見本の表」より前）。`NEAR` のとき近い形式の選択欄より後。値は回答の `formatId`・`formatName`。
3. **compact 3：**形式 ID を変えると回答が変わり、試し読みの結果と `formatHash` が消えて保存が押せない。欄の要素は同じまま（作り直さない）。取込中・保存後は `disabled` で、変更しても回答が変わらない。
4. **compact 4：**`customerSide` で［別の形式として登録する…］を押す前は、形式 ID・形式名の欄も見本の表も出ない。押した後は出る。
5. **compact 5：**金額の候補が 2 列以上で試し読みの結果があるとき、試し読みの結果に「金額の候補」と、候補ごとの行（合計・相違、選んでいる列に「（選択中）」）が出る。候補が 1 列以下、または試し読みの前は出ない。
6. **compact 6：**見本の表で列・行を変えても例外が出ず、表の選択欄と行の強調がそろう（なくした欄が無くても `formatRefreshVisuals` が動く）。

**既存のテストの扱い：**なくした欄（数値欄・プルダウン・金額のラジオ・出どころの表示・「列と形式の指定」の見出し）を前提にしたテストは、
- 同じ意味を見本の表の選択欄や回答で確かめられるものは、そう書き直す（例：プルダウンで列を変える → 表の選択欄で変える。数値欄で見出し行を変える → 表の行の選択欄で変える。ラジオで金額を変える → 表の「金額」で変える）。
- なくしたものそのものを確かめるだけのもの（出どころの文字、数値欄の入力途中の扱い、プルダウンの選択肢の文字の書き換え、ラジオの `checked` のそろえ）は、その確かめを消す。**消した確かめ・書き直したテストは全部、テストごとに 1 行で報告する。**
- ほかの確かめ（試し読みが消える・保存が押せない・確認のチェック・1 列 1 役・取込中や保存後に変わらない など）は弱めない。

## 5. 変異（H1〜H10）

- H1：「列と形式の指定」の見出しと欄を残す
- H2：形式 ID・形式名の欄を見本の表の後に置く
- H3：`customerSide` で登録を開く前にも形式 ID・形式名の欄を出す
- H4：形式 ID の変更が `formatUpdateAnswer` を通らない
- H5：形式 ID・形式名の欄を保存後に `disabled` にしない
- H6：試し読みの結果に金額の候補の比べを出さない
- H7：候補が 1 列のときも金額の候補の比べを出す
- H8：「（選択中）」を選んでいない列に付ける
- H9：「金額の列を確認した」のチェックを出さない
- H10：`formatRefreshVisuals` がなくした欄の配列を前提にして、表の変更で例外になる
