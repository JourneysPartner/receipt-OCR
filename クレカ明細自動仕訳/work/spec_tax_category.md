## 1. 何を作るか

### 1.1 背景（利用者の依頼と決定）

- **依頼（①、2026-11-15）：**転記シートの入力用シート G 列「相手税区分」を自動で入れる。取込用タブは、出金の行の借方税区分に入力用 G を使う（`spec_freee_export.md` §2.2）。G が空なら freee は勘定科目の税区分を使う。
- **今の作り：**G は顧客マスター AP 列（`columnMapping.G`、任意）に設定した顧客だけが書く。書くのは**カード会社からの返金（AO 列の店名）の行の「対象外」だけ**（`71` の 8-10）。ほかの行の G には触らない。
- **利用者の決定（2026-11-15）：**
  1. 基本は**勘定科目に対応する税区分**。**システム側の表（科目 → 税区分）で決める**（顧客の freee の勘定科目 CSV には freee の初期値が入っているだけなので使わない。保険料・支払利息は本来は非課仕入）。
  2. 例外を扱う：軽減 8%・フリマ（未登録の売り手）・少額特例・海外の物（輸入）・海外のサービス。
  3. 軽減 8% は**用途の言葉**（「食品」「食材」など）で決める。
  4. カードで払った先は原則インボイス登録事業者（＝課対仕入）。**メルカリ・ヤフオク・フリマは原則未登録**。
  5. 少額特例：フリマ等（未登録）で**税込 1 万円未満**は経過措置（控70 など）でなく課対仕入。**使える顧客が大半なので「使えない顧客」に印を付ける。**期限は 2029-09-30（国税庁）。
  6. 海外：取引先の印で分ける。**物の仕入＝課対輸本。サービス＝対象外**（リバースチャージのタグは付けない）。**海外のサービスでも 1 万円未満で少額特例が使えれば課対仕入 10%**（利用者の判断。Claude は法令で確かめていない）。「海外のサービス」は**消費者向け電気通信利用役務の提供**のこと。
  7. **例外を当てるかは勘定科目で決める**（仕入なのか事業主貸〔個人・私用に多い〕なのか。メルカリで私用なら対象外のまま）。
  8. 税率・控除割合・名前は**日付つきの表**で持ち、改正はデータの追加で済む作りにする。
  9. **決まらなければ空。**freee 取込用を出す前の確かめは「空は通す・一覧に無い名前は止める」（③ で実装済み）。
- **利用者の決定（2026-11-18）：**取引先の印は**まずマスターの表で付ける。「設定」の画面の欄は第 2 段**（印を足すときは利用者が Claude に言い、Claude が運用関数で入れる）。
- **利用者の決定（2026-11-18、§1.4）：**科目の表は Claude の案に次の直しを入れたもの（地代家賃・賃借料＝課対仕入、法定福利費＝非課仕入、給料手当・賞与・減価償却費・専従者給与＝対象外）。言葉は案のまま。軽減 8% は 2027-03-31 まで。
- **freee のヘルプで確かめたこと（2026-11-15、Orca のブラウザ。`spec_freee_export.md` §1.1 と同じ）：**率の無い「課対仕入」は 5% の税区分（だから G には必ず率を付ける）／`%` は半角、かっこは全角／経過措置は発生日で決まる（控80：2023-10-01〜2026-09-30、控70：2026-10-01〜2028-09-30、控50：2028-10-01〜2030-09-30、控30：2030-10-01〜2031-09-30）／輸入の本体は `課対輸本`（率なし）。**輸入の税区分は初期設定では使えず、顧客の freee で「使用」にする必要がある。**

## 2. 言葉と前提

### 2.1 言葉

| 言葉 | 意味 |
|---|---|
| G | 入力用シートの相手税区分の列（`customer.columnMapping.G`。TEST01 と登録した顧客は 7） |
| 税区分名 | freee の税区分の名前（`FREEE_TAX_CATEGORIES_` の `name`）。`%` は半角、かっこは全角 |
| 種類 | 科目ごとの税区分の大もと（§3.1）：`課対仕入`・`非課仕入`・`対象外` |
| 率 | `標準`（末尾 `10%`）・`軽減`（末尾 `8%（軽）`）。日付で決まる（§3.2） |
| 取引先の印 | 取引先名ごとの `フリマ`・`海外の物`・`海外のサービス`・`なし`（§4.1） |
| 少額特例 | 1 回の取引が税込 1 万円未満なら、インボイスが無くても仕入税額控除ができる特例（2023-10-01〜2029-09-30） |

### 2.2 今の G の書き方（変えない土台）

- `planned.g` が `undefined` の行は G に**一切書かない**（空も書かない。`43` の `buildRowWrite`・`writeTransactionRows`）。値があれば RAW の群で書き、読取確認（`verifyWrittenValues`）で比べ、取引ログの 46・47 列に予定値・確認値を持つ（`61`）。

- 本番の TEST01：G＝7、C＝3、AS＝`Q5:R49`、AL＝`[10, 14]`（G は空き判定の対象）、区分＝個人（2026-11-18 に読んで確かめた）。登録した顧客は TEST01 の AL〜AS を写すので同じ。

### 2.3 本仕様が効く顧客（`taxCategoryConfigured_(customer)`）

次を**全部**満たす顧客だけ。満たさない顧客は今の作り（返金の行だけ「対象外」）のまま、1 文字も変えない。

1. `columnMapping.G` が 1 以上の整数で、`rowScanExcludedColumns` に入っていない（G に雛形の既定値が無く、行を空ける所で G を空にできる）。
2. `columnMapping.C` が 1 以上の整数で、`accountListRange` がある（G は C で決まる）。

さらに、マスターの 2 つの表（§4）が**両方あり、見出しが正しい**ときだけ G を決める（＝本番では §9.1 で表を作るまで、今と同じに動く）。表が無い・見出しが違うときは、取込では今の作り（返金の行だけ「対象外」）。確定では（1.1）G に触らない（§6.2 の 2。1.0 では「決まらない」として空にしていた）。

### 3.2 率（`TAX_RATE_PERIODS_`）

| 率 | 末尾 | 始め | 終わり |
|---|---|---|---|
| `STANDARD` | `10%` | 2019-10-01 | なし |
| `REDUCED` | `8%（軽）` | 2019-10-01 | 2027-03-31（利用者の決定 2026-11-18。§1.4 の 3） |

- 利用日が、その率の行の期間（両端を含む）にちょうど 1 つ当たれば、その末尾。当たらなければ「決めない」（`RATE_PERIOD_MISSING`）。
- 改正のときは、今の行の終わりを前日にし、新しい行を足す（新しい名前は `46` の `FREEE_TAX_CATEGORIES_` にも足す。どちらも同じ push で）。

| 表 | 言葉 | 当たったとき |
|---|---|---|
| `TAX_REDUCED_WORDS_`（軽減 8% の言葉） | `食品`・`食材`・`食料品`・`食料` | 率を `REDUCED` にする |
| `TAX_REDUCED_EXCLUDE_WORDS_`（軽減にしない言葉） | `酒`・`アルコール`・`ビール`・`ワイン`・`外食`・`イートイン` | 軽減の言葉と両方当たったら「決めない」（`FOOD_AMBIGUOUS`）。軽減の言葉が無ければ何もしない |
| `TAX_UNDECIDED_WORDS_`（G を決めない言葉） | `消費税`・`リボ`・`分割` | 種類が `課対仕入` の行は「決めない」（`UNDECIDED_WORD`）。年会費の消費税だけの行・リボや分割の手数料（利息で非課税）に 10% を付けないため |

### 3.4 少額特例（`TAX_SMALL_AMOUNT_`）

`{from: '2023-10-01', to: '2029-09-30', limit: 10000}`。当たるのは：顧客が「少額特例を使えない」でない（§4.2）、かつ `Math.abs(金額) < 10000`、かつ利用日が期間の中。

### 3.5 経過措置

`FREEE_TAX_CATEGORIES_` のうち、名前が `課対仕入（控` で始まり、末尾が率の末尾（`10%`・`8%（軽）`）と同じで、期間（`from`〜`to`）に利用日が入るものが**ちょうど 1 つ**ならその名前。無ければ「決めない」（`TRANSITION_PERIOD_MISSING`。2023-09-30 以前・2031-10-01 以降）。

## 5. 決め方 `resolveTaxCategory_(input, tables)`（`48`、純粋な関数）

```
input = {customer, accountCode, purpose, date, amount, partnerName, cashback}
戻り値 = {status: 'DECIDED' | 'UNDECIDED', name, reason}
```

`name` は `DECIDED` のときだけ税区分名、ほかは `null`。`reason` は `UNDECIDED` のときだけ §5.2 のコード。上から順に：

1. `cashback === true` → `DECIDED`・`対象外`（今の作りと同じ。表が無くても）。
2. `tables.present !== true` → `UNDECIDED`・`TABLES_MISSING`。
3. `accountCode` が 1 以上の整数でない（数字だけの文字は整数として読む。`accountCodeValue_` と同じ）→ `NO_ACCOUNT`。
4. `TAX_ACCOUNT_RULES_` にそのコードが無い → `ACCOUNT_NOT_IN_TABLE`。
5. 種類が `対象外`・`非課仕入` → `DECIDED`・その種類（日付・金額・言葉・印を見ない）。
6. 種類が `課対仕入`：
   1. 用途が `TAX_UNDECIDED_WORDS_` に当たる → `UNDECIDED_WORD`。
   2. 軽減の言葉に当たり、軽減にしない言葉にも当たる → `FOOD_AMBIGUOUS`。軽減の言葉に当たる → 率 `REDUCED`、それ以外 → `STANDARD`。
   3. 利用日を読む（`yyyy-MM-dd`・`yyyy/MM/dd` の文字、または `Date`（東京の日付にする））。読めない → `DATE_INVALID`。§3.2 の期間に当たらない → `RATE_PERIOD_MISSING`。`suffix` を得る。
   4. 例外を当てない科目、または取引先名が空 → `課対仕入` + `suffix`。
   5. 印 `m = taxPartnerMark_(partnerName, customer.customerId, tables.marks)`：
      - `MARK_INVALID` → `MARK_INVALID`。
      - `なし` → `課対仕入` + `suffix`。
      - `フリマ`：金額が有限の数でない → `AMOUNT_INVALID`。顧客の設定が `CUSTOMER_FLAG_INVALID` → `CUSTOMER_FLAG_INVALID`。少額特例（§3.4）に当たる → `課対仕入` + `suffix`。当たらない → 経過措置（§3.5）の名前。無ければ `TRANSITION_PERIOD_MISSING`。
      - `海外の物` → `課対輸本`（率を付けない）。
      - `海外のサービス`：金額・顧客の設定は `フリマ` と同じに確かめる。少額特例に当たる → `課対仕入` + `suffix`。当たらない → `対象外`。
7. 最後に、決めた名前が `FREEE_TAX_CATEGORIES_` に完全一致であり、期間のある名前なら利用日がその中であること（二重の守り）。違えば `NAME_UNKNOWN`。
