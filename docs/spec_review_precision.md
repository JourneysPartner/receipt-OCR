# レシート OCR: 要確認を正しく減らす（桁の検査・O 列の書き方・計算の確かめ）仕様 1.0

対象は直下の `src/`（Python の Cloud Run Job）。クレカ明細（`クレカ明細自動仕訳/`）には触れない。土台は `docs/spec_read_quality.md`（両読み）、`docs/spec_duplicates.md`（重複）、`docs/spec_reader_compare.md`（読み手の比較と「形」）。

## 1. 目的

2026-11-20 のテスト記帳（25 枚）で、要確認（※）が 7 枚あった。利用者の指摘は 2 つ。

- 要確認が多い。中には誤って要確認になったものがある（画像からも文字からも 1,083 円で合っていたのに ※）。
- O 列（エラー詳細）がファイル全体の読みを並べるので、別のレシートを引きずったように見える。どの行の何が食い違ったのかが分からない。

この仕様は 3 つを直す。

| 部 | 中身 | 本番への効き方 |
|---|---|---|
| A 桁の検査 | 誤って「先頭の桁の読み違いの疑い」とする場合をなくす | push で効く |
| B O 列の書き方 | その行の何が食い違ったかを 1 文で書く | push で効く（書く文だけ。自動・要確認の判断は変えない） |
| C 計算の確かめ | レシートの中の計算（預り − お釣り、税抜 + 消費税）で金額を確かめる | 既定は切（今のまま）。比較で確かめてから利用者が決める |

もう 1 人の読み手（食い違ったときだけ別の読み手に読ませる）は `spec_reader_compare.md` の話で、ここには入れない。

## 3. 安全の条件（変えない。すべてテストで確かめる）

- P1 **A は疑いを増やさない**: 今「疑い」にならない金額は、直した後も「疑い」にならない。変わるのは §4 の場合が「疑い」でなくなることだけ。
- P2 **B は判断を変えない**: `reconcile` の戻り（合ったか・ラベル・理由・組にした位置）は、B の前後で 1 つも変わらない。変わるのは O 列と AI 詳細ログの文だけ。
- P3 **C は既定で何もしない**: `AI_CALC_CHECK=off`（既定）のとき、呼び出しの順・回数・表へ書く値・自動と要確認の分かれ方は今と同じ。
- P4 **C が自動にするのは §6.4 の場合だけ**: それ以外（日付の食い違い・明細の数の食い違い・相手の読みが無い・読み直しの守り・先頭の桁の疑い）は、計算が合っても要確認のまま。
- P5 **C は別の読み手の裏付けを必ず求める**: 計算に使う数（預り・お釣り、または税抜・消費税）は、画像からの読みにあるだけでは使わない。同じ数が Vision の文字の金額の候補（`extract_amount_candidates`）にもあるときだけ使う。
- P6 **C は値を書き換えない**: 表へ書く金額・日付は今までどおり画像からの読み。計算から金額を作って書かない。
- P7 **読み直しの守りが勝つ**: 前の回の印があるファイル（`_has_numbered_marks`）の未処理の明細は、計算が合っても `※再読取要確認` のまま。
- P8 **例外を投げない**: 新しい純粋な関数（§5 の文を作る関数・§6 の確かめ）は、欄が文字・真偽値・負の数・欠けていても例外を投げず、「確かめられない」として返す。
- P9 比較モード・重複・クレカ明細の安全の条件（`spec_model_compare.md` S1〜S8、`spec_read_quality.md` Q1〜Q6、`spec_duplicates.md` D1〜D8、`spec_reader_compare.md` R1〜R8）はすべて残す。

## 4. A 桁の検査の直し

今の決まり（`validate_amount`）: AI の金額が Vision の文字の候補に無く、4 桁以上で、先頭の 1 桁を取った残りが候補にあれば「先頭の桁の読み違いの疑い」（`digit_inflation`）。手書きの「¥」を 4 や 7 と読んだ場合（¥1,600 → 41600）を拾うため。

誤り: 1083 の先頭を取ると「083」で、これを 83 として候補を探していた。レシートに 83 円（消費税など）があると「疑い」になる。「¥」を数字と読み違えても、残りが 0 で始まる金額（¥083）にはならない。

直し:

- 先頭の 1 桁を取った残りの文字が `0` で始まるときは、「疑い」にしない（次の検査 `missing_in_ocr` へ進む）。
- ほかは変えない（4 桁以上・候補にあるときは `ok`・候補が無いときは `no_candidates`）。

効く所:

- 両読み: 画像からと文字からが合った明細を、この「疑い」だけで ※ にしていた分が自動になる（1,083 円の例）。
- 今までの流れ（`text_first`）: 同じ金額は `digit_inflation` でなく `missing_in_ocr` になる。どちらも金額の要確認なので、行の扱いは変わらない（理由の文だけ変わる）。
- 比較の道具: `score` をやり直すと、新しい検査で数え直される。

## 5. B O 列の書き方（両読みの要確認の行）

今: `両読み要確認（<理由>）: 画像=<日付>/<金額>, … ｜ 文字=<日付>/<金額>, …`（ファイル全体の読み）。

これから: O 列は **その行のことだけ** を 1 文で書く。ファイル全体の読み（今の文）は、AI 詳細ログの「メモ」に残す（`<新しい文> | <今の文>`）。調べるときはログを見る。

### 5.1 相手の決め方（文を作るためだけ。判断には使わない。P2）

画像からの明細 i に組（`text_index`）があればそれが相手。無ければ、どの組にも入っていない文字からの明細の中から次の順で 1 つ選ぶ。選べなければ「相手なし」。

1. 日付が同じもの（先頭から最初の 1 つ）。
2. 金額が同じもの（先頭から最初の 1 つ）。
3. 組の無い画像からの明細と、組の無い文字からの明細が、どちらもちょうど 1 つずつのとき、その 1 つ。

1 つの文字からの明細を 2 つの行の相手にしない（先の行が取ったものは、後の行は選ばない）。

### 5.2 文（N = 画像からの明細の数、M = 文字からの明細の数、X = この行の画像からの金額。金額は 3 桁区切りに「円」、読めていなければ「不明」。日付は `YYYY-MM-DD`、読めていなければ「不明」）

| 場合 | O 列の文 |
|---|---|
| 金額の食い違い（相手あり・日付は同じ） | `この行の金額: 画像から X 円 / 文字から Y 円（食い違い）` |
| 日付の食い違い（相手あり・金額は同じ） | `この行の日付: 画像から D1 / 文字から D2（食い違い）。金額は X 円で同じ` |
| 日付も金額も食い違い（相手あり） | `この行: 画像から D1・X 円 / 文字から D2・Y 円（日付も金額も食い違い）` |
| 相手なし | `画像からはレシート N 枚、文字からは M 枚と読みました。この行（X 円）は、文字からの読みに見当たりません` |
| 文字からの方が多い（`※明細数要確認`） | `画像からはレシート N 枚、文字からは M 枚と読みました（文字からの方が多い）。この行は画像から D1・X 円` |
| 文字からの読みが無い | `文字からは読めませんでした（画像からはレシート N 枚）。この行は画像から D1・X 円` |
| 画像からの読みが無い（文字からの明細を書いた行） | `画像からは読めませんでした。この行は文字からの読みです（D1・X 円）` |
| 先頭の桁の疑い（画像からと文字からは同じ） | `この行の金額 X 円は画像からも文字からも同じですが、先頭の 1 桁が余分な疑いがあります（文字の中に Z 円があります）`（Z = 先頭の 1 桁を取った金額） |
| 金額が 0 以下 | `この行の金額が読めていません（画像から X）` |
| 読み直しの守り（`※再読取要確認`） | `前の回と明細の数か並びが変わった疑いがあります。この行は画像から D1・X 円` |

- 「相手なし」で、組の無い文字からの明細が残っていれば、後ろに `（文字からの残り: <日付>/<金額>, …）` を 3 つまで足す。
- 短いラベル（N 列の `※金額要確認` など）は今のまま。
- 重複の注記（`spec_duplicates.md` §5・§11.3）は、今までどおりこの文の後ろに `／` でつなぐ。
- どちらも読めなかったファイルの 1 行（`AI抽出失敗（両読み）…`）と、今までの流れ（`text_first`）の文は変えない。
- 文を作る関数は `src/processing/reconcile.py` に置く純粋な関数（P8）。比較の道具の「読み」の欄は変えない。

## 6. C 計算の確かめ

食い違ったとき、どちらが正しいかは 2 つの読みだけでは分からない。レシートの中の計算が合い、その数を別の読み手（Vision）も読んでいれば、画像からの金額を正しいとみなせる。

### 6.1 指示文の第 3 版（`AI_PROMPT_VERSION=v3`）

第 3 版 = 第 2 版（重複の `time`・`receipt_no` を含む、その時点の文）＋ 次の 4 つの欄。第 1 版・第 2 版は 1 字も変えない。既定は第 2 版のまま。

- `pretax`: 消費税を足す前の金額の合計（「税抜」「外税対象」「小計（税抜）」など）。税込の小計は入れない。
- `tax`: 消費税の額の合計（8% と 10% が分かれていれば足す。「内消費税」も入れる）。
- `tendered`: お預かり（受け取った金額）。
- `change`: お釣り。
- どれも整数（円）。**レシートに書いてある数だけ**を入れ、計算して埋めない。書いていなければ null。

`src/models.py` の明細に同じ 4 つの欄を足す（既定は None）。`parse_receipt_items` は、欄が無い・整数でない・負の数なら None にする。第 1 版・第 2 版で読んだ明細は 4 つとも None（＝確かめは何もしない）。

### 6.2 確かめ（`src/rules/calc_check.py`。純粋な関数）

`calc_evidence(明細, Vision の文字) -> 証拠の並び`。候補 = `extract_amount_candidates(Vision の文字)`。金額 A は 1 以上の整数。

- **E1 預り − お釣り**: `tendered` と `change` がどちらも 1 以上で、`tendered − change == A`、かつ `tendered` と `change` がどちらも候補にある。
- **E2 税抜 + 消費税**: `pretax` と `tax` がどちらも 1 以上で、`pretax + tax == A`、かつ `pretax` と `tax` がどちらも候補にある。
- **E3 内税の税額（参考だけ）**: `tax` が 1 以上で候補にあり、A の 10/110 か 8/108 の切り捨て〜切り上げの間に `tax` がある。金額の下の桁の違いを見分けられないので、**自動には使わない**（注記だけ）。

証拠の文: E1 `預り 2,000 円 − お釣り 681 円 = 1,319 円`、E2 `税抜 1,200 円 + 消費税 119 円 = 1,319 円`、E3 `消費税 119 円と合う（参考）`。

### 6.3 環境変数 `AI_CALC_CHECK`

| 値 | 動き |
|---|---|
| `off`（既定） | 何もしない（P3） |
| `note` | 要確認の行の O 列の後ろに `／計算: <証拠の文>（画像からの金額と合います）` を足す。自動・要確認は変えない |
| `auto` | `note` に加え、§6.4 の場合に自動にする |

それ以外の値は終了コード 1。両読み（`AI_FLOW=dual`）のときだけ効く。

### 6.4 自動にする場合（`auto`。全部を満たすときだけ。P4・P5）

1. `reconcile` の判定が「金額が食い違う」（`※金額要確認`・組なし）。
2. 文字からの明細の数が、画像からの明細の数以下（`reconcile` が全部を要確認にする場合でない）。
3. §5.1 の相手があり、相手の日付がこの行の日付と同じ（日付は 2 つの読みで合っている）。
4. この行の画像からの明細に E1 か E2 の証拠がある。
5. 読み直しの守りに当たらない（P7）。

自動にした明細は、ほかの自動の明細と同じに書く（`【済】` の条件・重複の判断も同じ）。AI 詳細ログの抽出メモに `両読み=計算で確認（<証拠の文>） | <ファイル全体の読み>` と残す。

置き場: `reconcile` の後で判定を書き換える関数 `apply_calc_evidence(判定, 画像からの明細, 文字からの明細, Vision の文字, モード)` を `src/processing/reconcile.py` に置き、本番（`manager.py`）と比較の道具（`forms.py`）が同じ関数を呼ぶ。`off` と `note` では判定をそのまま返す。

### 6.5 自動にしない場合（記録）

- 文字からがそのレシートを読んでいない（相手なし）: 日付を確かめる相手がいない。もう 1 人の読み手（`spec_reader_compare.md` の形 B）の話。
- 手書きの領収書: 計算の欄が無いので証拠が出ない（人が見る）。
- 内税の税額だけのレシート（E3 だけ）: 注記まで。

### 6.6 比較で測る

- 比較の「明細JSON」に 4 つの鍵を足す（`pt`・`tx`・`td`・`ch`。None は書かない。今ある鍵は変えない）。古い結果（鍵なし）は今までどおり読める（証拠なしとして扱う）。
- 「形_<ラベル>」に、Vision を使う形（今・B）ごとに `＋計算` の行を足す（`apply_calc_evidence` を `auto` で通した成績。費用は元の形と同じ）。A2 は Vision を使わないので足さない。「形の明細_<ラベル>」の「判定」は、計算で自動にした明細を `一致（計算）` と書く。
- `score` は API を呼ばない（R5 のまま）。

### 6.7 本番に入れるまで

1. 実装（既定は `off`・第 2 版のまま）→ 監査 → push。本番の動きは変わらない。
2. 比較を `AI_PROMPT_VERSION=v3` で全部流す（読み手の比較と同じ回でよい）。
3. 見るもの: 第 3 版の日付・金額・税率・店名の正答率が第 2 版（`v2full-20261120` の low）より下がっていないか／`＋計算` で `誤って自動` が増えていないか／要確認がいくつ減るか／費用（出力が増える分）。
4. 利用者が決める: 既定を第 3 版にするか、`AI_CALC_CHECK` を `note` か `auto` にするか。切り替えは別のコミット（戻しはそのコミットを戻す）。
